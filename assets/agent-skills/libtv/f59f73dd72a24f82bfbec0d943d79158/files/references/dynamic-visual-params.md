# 动态视觉参数：网页适配版

此版本仅包含网页可导入的 Markdown，不含本地脚本或状态模板。执行者使用当前环境**实际提供**且可回读的项目工作文件或记录工具；若没有持久记录能力，则在任务结果中列明全部参数与缺口，不得虚构已保存状态。工作文件和对话不等同于画布节点。不同场景分别记录，不覆盖历史。

## 逐项建立参数记录

以用户原话、当前参考素材、工具能力和已有状态为输入。每条独立记录：用户原话及决定来源、变化对象与具体部位、视觉要素、优先级（必须保留／加强／允许变化／禁止新增／尚未确认）、类型（数值／结构／程度）、允许范围或目标值及单位、验证方式与证据、实际结果、状态和修改历史。区分产品本体的属性效果与独立物体或新结构；尚未确认既不视作允许变化，也不默认全部锁死。含否定或多个诉求先拆解；“不要改变”是保持，不等于删除。无法从用户或可靠证据获得的数值写“未指定”，不擅自赋值。

可用视觉工具时以实际可访问素材记录可见事实；否则只记录用户明确描述，其余标未知。程度档位 1–5 与不适度 0–4 为不同量表，不能直接互换。验证方式只能依据实际可用并可靠的工具：视觉模型提供可追溯的定性观察；用户评价只记录真实反馈；数值检测需要经验证的方法和可复核证据，不能把模型文字变为面积或色差测量。

## 根据反馈调整

用户要求增加、减少、禁止或保留时，先确定对应唯一参数及目标方向；不明确、基线缺失、多个目标可能匹配时询问，不猜测。能确定数值基线时，默认相对调整幅度 10%，用户明确指定时依其要求；合理边界内限制，百分比不超过 100%。程度调整一档、限制在对应量表范围。结构变更以用户明确要求表述，不虚构坐标或数字。保留变更前后、原因、时间和原话，并将有关结果重置为待核；修改参数记录不代表画布节点已修改。

## 逐项验证与失败处理

逐项记录要求、目标、实际观察、来源和状态：通过／未通过／未验证／待用户确认。只有存在经验证的检测方法、具体量化目标与可复核测量，才比较数值范围；图像遮挡、缺掩膜、视觉模型仅有定性描述或无用户主观评价时标未验证。对失败项提出有针对性的修正建议并保留原目标及历史，提交重试前展示当前报价并由用户决定，失败不自动重试。

## 输出

可回读的当前场景参数记录、与实际画布节点的对应关系、逐项证据及状态。记录缺失、不可回读或无法测量时明确说明；生成任务成功和用户最终验收是独立结果。

## 本版补充规则


每个任务独立建立可回读记录，不继承其他商品、清洁球或项目的未授权参数。按用户原话与当前画面建立适用项，记录来源节点 ID、原话、视觉要素、目标、证据和状态。约束可标 MUST_KEEP、ALLOWED_CHANGE、MUST_STRENGTHEN、MUST_NOT_APPEAR；未知为 UNKNOWN，不适用为 NOT_APPLICABLE，需要用户判断为 NEEDS_HUMAN。不得为了填表而虚构数值或素材事实。用户反馈时仅修改对应目标，保留历史及其他固定项，若冲突则报告请用户决策。

根据实际可用能力选择检测方法；模型描述不是客观测量。无法可靠测量保留 UNKNOWN，主观评价由用户确认。生成前展示当前报价并由用户决定；失败不自动重试。


## 长文本与状态隔离
保留各场景用户原话、参数来源、变更前后、结果与确认。M2 和每组 M5 采用用户确认的当前正文；用户删除或否定的内容检查其同义表达，防止从旧种子、摘要或模板重新进入节点和待提交输入。长文本无法完整写入或回读时如实标未验证，说明具体缺失能力并请求最少人工补位；不要求用户建立中转文本节点或到外部文件搬运正文。历史版本保留但不作为当前输入。
