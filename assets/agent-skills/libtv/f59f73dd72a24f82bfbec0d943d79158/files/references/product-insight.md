# 产品信息与消费者洞察

当用户提供产品详情页、产品说明、演示视频或评论，并要求产品分析或用于裂变建议时执行；完整的六部分分析要求以 `product-insight-source.md` 为准。只使用用户提供且可读取的资料，不以网页经验或其他商品补充事实。图片、产品详情和评论缺少任一项时继续处理已有材料，并说明哪些部分资料不足。

先分别处理商品资料与评论，再比较：商品内容标记为“商家宣称 / 参数标注 / 画面可见或视频展示”，评论标记原始来源、购买状态是否明确、重复与不可辨认情况；不得把商家宣传或用户评价直接当作经过验证的客观性能。区分原文事实、样本现象、有依据的解释和待验证假设，标识证据来源。给素材编号 P001、P002……，视频 V001……，评论 C001……，保留引用和可追溯性。

评论清洗要保留完整语义和反例；删除无信息或重复表达但不删除负面意见。一个评论可关联多个主题，但统计原始有效评论时只计一次；无法辨认账号或评论总数时标明无法统计，不凭局部截图估计总体比例，不把未确认购买状态归为已购。

分析交付保持用户提供的六部分结构：01 产品基础信息；02 产品功能、宣传主张与证据边界；03 商品详情及视频展示内容；04 评论信息统计、观点提取及现象；05 基于证据的人群、生活情境、心像与情感共鸣；06 有依据的消费者洞察、其他解释、判断状态及待验证问题；最后列输入资料及缺口。资料不足的部分明确标出，不为凑数编造。人群与洞察是有证据的理解和假设，不给出广告策略、卖点排序、脚本或创意方向。

完成分析之后，作为独立的后续裂变步骤，根据资料中实际支持的用途、场景、用户任务和局限，以及优化反推场景词，提出允许变化的场景、环境物体、风格、动作等建议；每项标注基于哪条商品资料或评论，区分用户素材中的事实、商家宣称、评论描述、分析假设与创意建议。建议不是产品功效证明或消费者普遍结论；不擅自加入未经证实的功效或演示前后结果。用户明确锁定或排除的内容优先，变化维度和范围按用户要求选择。不得把此步骤写进六部分产品分析报告冒充分析结论。

在用户要求画布工作时，产品资料与评论汇入可见的“产品分析”文本节点；实际保存全文并尽量扩大节点以便阅读。记录来源节点与分析节点，确认节点确实存在且可编辑或如实说明限制。不要把本地报告或聊天回答称为已创建画布节点。
