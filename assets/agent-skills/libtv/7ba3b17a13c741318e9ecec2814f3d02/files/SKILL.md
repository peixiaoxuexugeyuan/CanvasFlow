**长棍武器快速动作描述生成（写实电影版）**

description：为 wan3.0prime 视频生成模型输出高质量长柄武器战斗动作提示词。

版本字段：V1.0

核心体验：一个武艺高强的战士以碾压性的速度优势冲入敌群中，动作凌厉，一击即溃，敌人根本来不及反应。每一个动作都有清晰的受击反馈——敌人被击中时的身体反应、倒地姿态、装备崩落、痛觉表现都必须具体可见。

# **设计哲学**

## **四大核心支柱**

**• 速度碾压感** — 主角的每一个动作都明显快于敌人，形成视觉上的绝对压制。敌人举盾、转身、张嘴的反应时间永远慢半拍以上。

**• 物理写实感** — 所有视觉反馈必须有真实物理来源。重量、惯性、摩擦、呼吸、汗水、尘土，一切都有因果。

**• 受击反馈感** — 每一次命中都必须有明确的受击者反馈。被击中的敌人不是凭空消失，而是有具体的身体反应：踉跄后退、弯腰弓背、侧身倒地、盾牌碎裂、甲片崩落、头盔飞脱、面部扭曲、四肢失控。受击反馈是动作"有力量"的核心证据。

**• 电影镜头感** — 不是游戏过场动画，是动作电影的运镜。每一次景别切换、每一个运镜动作都为叙事服务。

**• 模糊描述**："快速攻击""猛烈打击""强大的力量" — 必须具体到动作轨迹、身体部位、物理反馈

## **绝对禁止**

**• 修仙/玄幻特效**：冲击波、速度线、能量聚集、碎石悬浮、空气扭曲、闪光、发光、气场、力量涌动

**• 游戏化表现**：伤害数字、血条、技能冷却、瞬移、残影

**• 物理违背**：无来源的碎片飞溅、无重力的跳跃、违反惯性的急停

**• 受击消失**：被击中的敌人不能"凭空消失"或"直接不见了"，必须有明确的倒地/后退/飞出去的过程

# **触发条件**

• 为 wan3.0prime 生成武器战斗动作视频提示词

• 设计方天画戟、长枪、棍棒等长柄武器的动作序列

• 生成1秒内多动作的快速战斗描述

• 需要体现蓄力、爆发、冲刺、穿插交手、奔跑等动作层次

• 制作冷兵器战斗分镜或动作编排

# **输入参数**

**• 武器类型**：方天画戟 / 长枪 / 棍棒 / 三尖两刃刀 / 自定义（默认：方天画戟）

**• 角色描述**：外观、体型、服饰风格（默认：体格精壮）

**• 敌方类型**：小兵 / 精英兵 / 混合（默认：小怪，小兵群体，甲胄简陋，动作迟缓）

**• 场景环境**：战场类型（默认：旷野黄土战场）

**• 动作时长**：总时长秒数（默认：1秒）

**• 摄影机风格**：固定/跟拍/环绕/俯拍/混合/无人机拍摄（默认：混合动态镜头）

**• 画面风格**：写实/半写实/暗黑（默认：写实电影感）

**• 速度倍率**：主角相对敌人的速度感知（默认：碾压级，敌人几乎来不及反应）

若用户只说"帮我生成一个方天画戟的动作描述"，直接用默认值执行，不追问。

# **生成流程**

## **第一步：确认参数**

读取用户输入，补全缺失参数为默认值，在输出开头列出本次使用的参数。

## **第二步：构建动作时间轴**

按动作密度 = 3个动作/秒 拆分时间轴，每个动作分配约 0.33 秒。

• Beat 1（0.00–0.33s）：蓄力 / 起跑蓄力

• Beat 2（0.33–0.66s）：爆发 / 冲刺攻击

• Beat 3（0.66–1.00s）：穿插突破 / 奔跑收尾

扩展：2秒6拍（蓄力→爆发→爆发→冲刺→穿插→奔跑）；3秒9拍。

## **第三步：选取动作片段**

从 references-[action-library.md](http://action-library.md) 选取。每个片段含：动作名称、身体力学、速度对比、受击反馈、空间层次、环境交互、镜头指令。

约束：相邻 Beat 不可同类型；蓄力必须紧邻爆发；景别至少跳一档；动作总数 = 时长 × 3。

## **第四步：组装 wan3.0prime 提示词**

**• 动词驱动**：slams, sweeps, thrusts, dashes, hurls（避免 moves, goes, is）

**• 速度对比必写**：每个 Beat 至少一个速度对比细节

**• 受击反馈必写**：每次命中必须描述敌人的具体受击反应（参考 [reaction-library.md](http://reaction-library.md)）

**• 空间锚点**：前景/中景/远景

**• 物理细节**：weight shift, momentum, recoil, heavy breathing, sweat flicking, robes streaming, dust kicking

**• 环境交互**：每个 Beat 至少一个具体物理交互

**• 镜头语言**：参考 [camera-choreography.md](http://camera-choreography.md)

**• 节奏标记**：in the same motion, before the dust settles, the momentum carrying him

# **动作设计原则**

## **一、速度碾压系统**

四个层级：反应差（敌人反应跟不上）、动作差（敌人做一个主角做多个）、感知差（敌人不知发生了什么）、群体崩溃（多人连锁击溃）。必须嵌入每个 Beat。

完整描写见 references-[reaction-library.md](http://reaction-library.md)。

## **二、受击反馈系统（核心机制）**

四层：即时身体反应（面部扭曲/头部甩动）→ 躯干四肢反应（弯腰弓背/手臂瘫软/膝盖弯折）→ 倒地飞出姿态（侧飞/滑行/坍塌/弹射）→ 装备环境反馈（盾碎/甲崩/头盔飞脱/地面拖痕）。

每次命中至少覆盖前两层。完整描写见 references-[reaction-library.md](http://reaction-library.md)。

## **三、空间层次**

每个 Beat 至少两个空间层：前景（武器轨迹/碎片/被击飞敌人）、中景（主角全身/武器整体）、远景（敌军队列/战场环境/天空）。

## **四-七、蓄力/爆发/冲刺穿插/奔跑**

各阶段必须包含：身体力学描述 + 环境交互 + 速度对比锚点 + 受击反馈（若命中）。

## **八、环境交互系统**

按场景调整：旷野（扬尘泥块）、石面（刮擦火星）、密林（枯枝落叶）、水边（水花涟漪）、废墟（瓦砾灰尘）、雪地（雪块雪雾）、马戏团帐篷区（帆布撕裂/绳索削断/帐篷撞穿/道具堆滚入）。

# **约束规则**

1\. 动作总数 = 时长 × 3

2\. 蓄力必须紧邻爆发

3\. 相邻 Beat 不可同类型

4\. 景别至少跳一档

5\. 禁止模糊描述

6\. 英文提示词不用中文

7\. 禁止修仙/玄幻/游戏词汇

8\. 每个 Beat 至少一个环境交互

9\. 每个 Beat 至少一个速度对比

**10. 每次命中必须有受击反馈（至少前两层）**

11\. 反向提示词必须输出
