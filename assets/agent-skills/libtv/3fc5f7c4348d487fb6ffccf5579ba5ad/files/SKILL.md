# 小说转影视剧本

把用户提供的小说原文改编成**剧本体的创作稿**，供后续视频制作流程（`libtv/basic-video-production`）取材。

## 一、授权声明（本 skill 的生效前提）

- 本 skill **只在用户明确要求"把小说改编成剧本"时使用**。用户没有明确授权改编时，不要主动把小说文本改写成剧本体。
- 本 skill 生效时，其改编规则**优先于** `libtv/basic-video-production` 的 `specs/draft.md` 中「用户提供的小说文本不得改写成剧本体」这一默认约束。该默认约束的立法目的是防止 Agent 未经授权擅自改写用户素材；本 skill 正是那个"用户明确要求改编"的授权场景，因此在生效范围内覆盖该默认约束。
- 覆盖范围**仅限于改编动作本身**。后续的总表、锚点登记、分镜拆分等环节，仍按 `libtv/basic-video-production` 的规范执行，本 skill 不改变这些环节的默认约束。
- 本 skill 是**环节工具**：只负责产出剧本体创作稿，不负责分镜、资产图与成片。

## 二、改编总原则

1. **不篡改事实**：情节推进顺序、关键事件、人物关系与因果链不得改动。改编改变的是"呈现方式"，不是"发生了什么"。
2. **忠于原著对白**：原著对白尽量逐字保留。
3. **一切可拍见**：最终稿里不应存在摄影机拍不到的表述。
4. **按爆款漫剧逻辑取舍**：删减与合并由本 skill 按短剧/漫剧的改编逻辑自行判断，不逐次询问用户；成稿时附**取舍清单**供用户事后核查（详见第五节、第八节）。
5. **先确认再落地**：改编稿另存新文件，原文件不动，经用户确认后才成为唯一基准（详见第九节）。

## 三、工作步骤

### 步骤 1：通读原文，确认改编范围与目标

通读全文后，先与用户对齐三件事（缺哪项问哪项）：

- **改编范围**：哪几章 / 哪一段 / 全文？
- **目标体裁**：短剧（竖屏、单集 1–3 分钟）、剧集（横屏、单集 20–45 分钟）、单集电影式短片，还是舞台剧式剧本？
- **目标用途与时长**：拍成几条、每条多长？

用户未指定时，默认按**竖屏短剧**处理，并在交付时说明所采用的默认值。范围与目标确认后再动笔，避免整篇改完才发现方向不对。

### 步骤 2：拆分场次

**一个场景一场，标场号，从 1 起连续编号。**

切分判据（满足任一即换场）：

| 判据 | 说明 |
|---|---|
| 时空转换 | 地点变了，或时间跳了（日→夜、当天→次日、现在→回忆） |
| 主要人物进出 | 核心人物进场或离场，改变了在场关系 |
| 戏剧动作完成 | 一个完整的戏剧动作（一次交锋、一个决定、一次揭示）已经收束 |

同一地点、同一时间、人物进出但动作连续不断的，可保留为一场，用"（某人上/下）"标注，不必强行拆碎。

### 步骤 3：按规范写每一场

**场头行**（固定格式，一场一行）：

```
场号 + 内/外景 + 日/夜 + 场景名
```

示例：`1. 内景 夜 老宅书房`

**环境/氛围简述**：场头下用一段简短文字交代空间、光线、天气、时代特征、可感知的声音。只写能被拍到的信息，不写"气氛压抑得让人喘不过气"这类不可拍的判断，要写成"雨点砸在窗玻璃上，台灯只亮了半边，墙上挂钟指针停在三点"。

**动作行**：

- 用**现在时**。
- 只写**可拍见的画面**：动作、神态、物件、镜头可感知的信息（光线、声音、气味引起的可见反应）。
- 不写人物内心、不写作者评论、不写镜头语言之外的抽象概括。
- 每段动作行聚焦一个可执行的视觉单元，便于后续拆分镜。

**台词行**：

- **独立成行**，标注说话人，格式：`角色名：台词内容`
- 台词行与动作行交替排列，不混在一段里。

**括注**（写在台词前或台词中，用圆括号）：

- 语气/情绪：`（低声）`
- 画外音：`（V.O.）`
- 内心独白：`（O.S.）`
- 旁白：`（旁白）`
- 字幕：`（字幕：……）`
- 闪回标记：`（闪回）` / `（闪回结束）`

**格式示例**：

```
1. 内景 夜 老宅书房

雨点砸在窗玻璃上。台灯只亮了半边，墙上挂钟停在三点。
林砚推门进来，手里攥着一封信，指节发白。

林砚：（压着声音）爸，这封信是什么时候到的？

林父没有抬头。他把烟按进烟灰缸，来回碾了两下。

林父：你妈走的那天。

（字幕：三十年前）
```

### 步骤 4：转化心理活动与非画面信息

这是改编中最容易偷懒的一步，逐条按下面顺序处理：

1. **优先转为可拍见的外部表现**：内心独白 → 神态、微表情、肢体细节、动作停顿、物件处理方式（把信折起来又展开、把杯子推远一寸）。原著的"他想起了……"→ 让他看向某物，或手指停在某物上。
2. **其次转为对白**：能让人物说出口的，就让他说（可拆给对手戏角色，形成交锋）。
3. **再次转为环境外化**：用可见的环境变化呼应情绪（灯灭了、雨大了、手机屏幕亮起又暗下）。
4. **最后才用画外音/旁白/字幕**：仅在上面三条都做不到、且该信息对理解剧情不可缺时使用。

**允许保留旁白的情形**（明确限定）：

- 原著以第一人称叙述，且叙述者视角本身是作品的叙事装置；
- 需要交代大跨度时间/背景信息，画面无法在短时长内承载；
- 章回体/文言原文的叙述腔调本身构成风格，需保留其韵味；
- 用户明确要求保留旁白。

除以上情形外，**不要把大段心理描写直接搬成旁白**——短剧/漫剧的节奏不允许，旁白堆叠会显著降低可看性。

### 步骤 5：原著叙述的取舍原则

**必须保留（不得篡改）**：

- 情节推进顺序
- 关键事件（人物命运的转折点、决定性行动）
- 人物关系与因果链

**对白的处理**：

- 尽量逐字保留。
- 确需压缩的判据：① 单条台词过长，超过该体裁单句可承载的时长；② 内容与前后台词重复；③ 包含大量书面语/文言，说出来不像人话。
- 压缩方式：保留核心信息与标志性措辞，删去修饰性铺陈；**不得改变说话人的立场、态度与信息量**。

**描写性文字的处理**：

- 降级为**动作行**与**环境行**，不整段丢弃。
- 不遗漏影响画面的信息：**服装、道具、光线、天气、时代特征**。这些是后续美术与分镜的依据，漏掉会导致成片与原著质感脱节。
- 不可拍的抽象描写（议论、抒情、作者旁白式总结）→ 按步骤 4 转化，或按步骤 6 删减。

### 步骤 6：按爆款漫剧逻辑删减与合并

**本 skill 自行判断，不逐次询问用户**；成稿时附取舍清单供事后核查。

**可删可并的**：

- 拖节奏的支线：与主线因果无关、不改变任何人物处境、删掉后不影响理解的情节线。
- 纯叙述：作者的背景铺陈、议论、抒情，且信息已由画面或对白承载。
- 重复描写：同一信息在不同章节反复出现，保留最早或最有力的一处。
- 无戏剧功能的过场：单纯的位移、等待、日常起居，除非本身承担情绪或伏笔功能。

**必须强化的（爆款漫剧逻辑的核心）**：

- **冲突密度**：把原著中分散的冲突集中到同一场次，缩短铺垫，让矛盾尽早正面相撞。
- **情绪爽点**：放大原著中已有的打脸、逆袭、揭穿、护短、破防等情绪高点，给足反应镜头与台词空间。
- **反转与钩子**：识别原著中的信息落差，把它安排在场次末尾或集末，形成钩子。
- **开场即入戏**：短剧第一集开头不铺背景，直接进入冲突或悬念，背景信息拆散后嵌入后续场次。

**红线**：删减合并**不得改变主线因果、人物核心动机与结局走向**。删的是"怎么讲"，不是"讲了什么"。

### 步骤 7：分集/分段建议

**默认按短剧节奏切分**，每集结构：

| 位置 | 功能 |
|---|---|
| 开场（前 5–10 秒） | 钩子——悬念、冲突或反常识画面，直接抓住观众 |
| 中段 | 升级——冲突加剧，信息量推进，人物处境变差或变复杂 |
| 结尾 | 悬念——在情绪或信息上留一个未闭合的口子 |

输出**分集区间表**，每集一行，标明：

- 集号
- 本集覆盖的**原文区间**（章节号/段落起止，便于回溯核对）
- 本集对应的**场号范围**
- 本集的钩子与结尾悬念各是什么

用户指定了单集时长时，按用户时长切分，其余规则不变。

### 步骤 8：自检清单

逐场核对，全部通过才算完成：

- [ ] 原文关键情节是否有遗漏？
- [ ] 原文关键台词是否保留（或按判据压缩且未改变信息量）？
- [ ] 说话人归属是否正确？有无张冠李戴或合并了两个角色的台词？
- [ ] 是否存在不可拍的抽象表述（心理、议论、抒情）未被转化？
- [ ] 动作行是否统一使用现在时？
- [ ] 场头格式是否统一（场号 + 内/外景 + 日/夜 + 场景名）？
- [ ] 台词是否独立成行、标注说话人？
- [ ] 括注是否规范（语气 / V.O. / O.S. / 旁白 / 字幕 / 闪回）？
- [ ] 影响画面的信息（服装、道具、光线、天气、时代特征）是否遗漏？
- [ ] 每集是否都有开场钩子与结尾悬念？
- [ ] 分集区间表是否与正文场号一一对应？
- [ ] 取舍清单是否已列出所有删改内容及原位置？

### 步骤 9：产物落地与衔接

**落地方式**：

1. 改编稿**另存为新的创作稿文件**，放在 `/drafts` 下，以 **task id 命名**（如 `/drafts/{task_id}-script.md`）。
2. **原文件保留不动**，不覆盖、不改名、不移动。
3. 用 `ask_human` 请用户确认。**确认后，该改编稿才成为唯一基准**；未确认前，原小说文本仍是基准，不要把改编稿当既定事实往下推进。
4. 用户提出修改时，改的是新稿，仍不动原文件。

**与 `libtv/basic-video-production` 的衔接**（确认之后才执行）：

1. 进入总表
2. 锚点登记
3. 分镜拆分

衔接环节的规范以 `libtv/basic-video-production` 为准，本 skill 只负责把剧本稿交出去。

## 四、交付物清单

一次完整的改编应交付：

1. **剧本体创作稿**（`/drafts/{task_id}-script.md`）——分场、分集、格式规范
2. **取舍清单**——列出所有被删、被并、被压缩的内容及其原文位置与理由
3. **分集区间表**——每集覆盖的原文区间、场号范围、钩子与悬念

## 五、常见错误

- 把心理描写整段搬成旁白，导致旁白密度过高、节奏拖沓。
- 为了"忠于原著"保留大量无戏剧功能的过场，短剧节奏垮掉。
- 擅自改动情节因果或人物动机，超出授权范围。
- 场头格式不统一、台词与动作混排，后续分镜无法机械解析。
- 直接覆盖原文件，导致用户原始素材丢失。
- 未确认就把改编稿当基准，继续往下做分镜与资产。
