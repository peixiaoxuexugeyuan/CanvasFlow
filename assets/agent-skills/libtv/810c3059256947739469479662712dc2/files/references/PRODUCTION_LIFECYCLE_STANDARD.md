# 制作版本、生成轮次与成片接受

本文件补充主文件第2、4、10、13、14节，不定义新的用户页面。

## 身份链

源媒体/source_revision → 批准制作production_revision（含剧本/执行/表演/对白/资产依赖）→ 冻结Prompt/参数 → attempt_id/真实节点 → as_generated_snapshot/原始生成文件 → 经过检查的派生剪辑版 → accepted_artifact_id → 适用连续性素材。

源RAW数量不可被制作改编重写。STRICT用源ID映射核对；USER_MODIFIED另设TARGET数量与批准差异。拆段每个part只核对分配给它的事件，父段按稳定ID合并；跨段同一D父ID只计一次。

## 变更与批准

每个批准附用户原话、对象revision与依赖。表演批准后存DIRECTED_EMOTION，编译不能回读旧源表情；场景/道具的功能变更会影响空间/站位/动作，重新复核相关项。单纯色调修改不重问不相关台词。冻结后Prompt/参数/绑定任一变化重新冻结；不把自然语言“继续”当作新方案、配置差异或全部制作缺陷的通用批准。

## 操作与重试

辅助资产用本地截图/裁切/像素分析/SVG制作，不调用付费生成。文件制作后还要真实挂载并拿key，冻结前清单和Prompt引用一致。13A写入中断先读取同attempt准备节点后补齐，防重复创建；已提交节点不回写新方案，另建attempt。创建超时无key时按主文13A先反查；无法唯一定位或工具不支持则停下，不盲目重建。正式视频始终由用户点击生成，不自动重试。

## 实际生成记录与候选片

提交后记录能核实的实际Prompt/参数/绑定/任务关联；unknown保留unknown。最终导出尺寸不等于生成时设置，无法从视频推断模型身份或输入资产。用户生成时改画幅后，旧片仍按实际生成版本记，重编Prompt属于新方案，不能让旧片取得新方案来源。

若旧片可用：检查真实内容，列出相对批准方案的实际差异，用户明确接受后可ACCEPTED_WITH_DEVIATIONS。若需修复：留POST_GENERATION，给差异→影响→对应审核→新attempt方案；用户批准且节点就绪后自行生成。旧片和旧冻结都保留，不以新文字覆盖历史证据。

## 验收、裁切与接受

先检查原始回片完整事件，再决定能否按批准终点裁切。例：正文10秒、输出13秒，末句到12秒才结束——不能裁到10秒宣布完成；应NEEDS_FIX，建议重生成控制节奏，或在用户明确批准新目标时长/剪辑并验证后接受派生版。批准加长不是重生成，不改写旧片实际来源。

| verification_mode | 允许结论 |
| --- | --- |
| FILE_INSPECTED | 对实际检查项给证据；有真实配置证据才声称与冻结一致 |
| FILE_INSPECTED_CONFIG_UNVERIFIED | 可做实际内容检查；配置来源缺口明确披露，用户接受可观察结果及未知配置后可指定接受版 |
| USER_DESCRIPTION_ONLY | 只能轻量核对描述，不验收通过、不派生连续性、不NEXT |

QA结果PENDING/NEEDS_FIX/PASS/ACCEPTED_WITH_DEVIATIONS和verification_mode分开存。PASS不是“工具跑过”；要有必要实际内容检查。任何未检查必要项不能由用户描述伪装完成。制作偏差可明确接受，内容/授权及接口HARD不可豁免。

接受版需指向具体文件/剪辑版本与attempt，保存偏差清单及用户决定；只有PASS或明确接受偏差后指定accepted_artifact_id。NEEDS_FIX仍可向用户展示候选和修复建议，不派生正式下一段资产。用户明确放弃衔接另开RESET时，前段未接受状态保留。

## 连续性与短片

下一段收到源视频后先判DIRECT/CUT/RESET，再应用适用继承。DIRECT/CUT色卡只从接受版真实取样；RESET跳过前段站位/色卡，照新场景准备。尾段样本[max(0,T-5s),T]；衔接视频另须3–5秒且用户OPT_IN，T<3s保持关闭。替换接受版使旧派生素材及依赖批准失效。

## 常见错误

- 修改RAW数量来让制作对账通过：改为保留RAW，批准TARGET差异。
- 情绪表批准后仍从反推账本编译：读取批准DIRECTED_EMOTION。
- 只看到视频足够长就裁尾：先核对末句/动作/END完成点。
- 检查出漏句仍准备下一段：先NEEDS_FIX，返工或明确接受具体偏差。
- 新场景套旧末帧位置/色卡：先判RESET。
- 新Prompt批准后给旧片标“新方案生成”：分别记录实际片源与新attempt。
